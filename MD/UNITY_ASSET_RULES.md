# Unity 에셋 생성 및 관리 규칙

이 문서는 Unity 에셋의 생성·수정·이동·삭제 시 참조와 기존 구성을 보존하기 위한 공통 규칙이다. 씬, 프리팹, 머티리얼, 텍스처, 모델, 오디오, 애니메이션 및 ScriptableObject 에셋에 적용한다.

> 사용자 지시와 적용되는 `AGENTS.md`를 우선한다. 파일 형식은 `FILE.md`, C# 구현은 `UNITY_CS_CODING_RULES.md`, 빌드 검증은 `BUILD.md`를 따른다.

---

## 1. 작업 전 확인

1. 현재 Unity 버전, 렌더 파이프라인 및 관련 패키지를 확인한다.
2. 같은 역할의 기존 에셋과 폴더·명명 규칙을 확인한다.
3. 변경 대상이 원본 에셋, Prefab Variant, 씬 인스턴스 또는 패키지 제공 에셋인지 구분한다.
4. 관련 씬·프리팹·설정의 참조와 사용 범위를 확인한다.
5. 기존 사용자 변경과 저장되지 않은 Editor 작업에 영향을 주는지 확인한다.
6. 관련 Unity Skill이 있으면 해당 절차를 확인한다.
7. CLI·MCP·Pipeline 전체 점검의 시점은 UNITY_TOOLING.md를 따른다. 에셋마다 최신 조회를 반복하지 않되, 수정할 Editor·프로젝트·씬이 맞는지는 실제 작업 전에 확인한다.

이 문서의 예시는 기존 구조가 없을 때 참고한다. 폴더 구조를 맞추기 위한 일괄 이동은 별도 요청 없이 수행하지 않는다.

---

## 2. 폴더와 이름

프로젝트 고유 에셋은 기존 전용 폴더에 모으고 외부 패키지와 구분한다.

```text
Assets/<ProjectName>/
├── Animations/
├── Audio/
├── Materials/
├── Models/
├── Prefabs/
├── Scenes/
├── ScriptableObjects/
├── Sprites/
├── Textures/
└── UI/                  # 필요할 때만 추가
    ├── UXML/
    ├── USS/
    ├── Panels/
    └── Fonts/
```

- 필요한 폴더만 만들고 기존 분류 방식을 유지한다.
- 이름은 용도와 대상을 알 수 있게 작성한다. 예: `Player.prefab`, `Login.unity`.
- 접두사와 접미사는 프로젝트에 이미 정해진 방식이 있으면 따른다.
- `New Material`, `Test1`, `Final_V2`처럼 역할을 구분하기 어려운 이름을 피한다.
- 대소문자만 다른 파일 이름을 새로 만들지 않는다.
- `Resources`, `StreamingAssets`, `Editor`처럼 Unity가 특별하게 처리하는 폴더는 용도를 확인한 뒤 사용한다.

---

## 3. .meta와 GUID 보존

- 기존 에셋을 이동하거나 이름을 바꿀 때 `.meta`와 GUID를 보존한다.
- 가능하면 Unity Editor 또는 해당 버전에서 지원되는 Editor API를 통해 이동·이름 변경을 수행한다.
- 파일 시스템에서 이동해야 한다면 에셋과 대응하는 `.meta`를 함께 처리하고 재임포트 후 참조를 검증한다.
- 폴더의 `.meta`도 보존 대상으로 취급한다.
- Assets 아래 새 스크립트를 포함한 새 에셋의 `.meta`는 Unity가 생성하도록 하고 새 GUID를 임의로 작성하지 않는다. Editor를 사용할 수 없어 생성·참조 검증이 남으면 미완료 항목을 보고하고, 실제 프로젝트 반영에 필수이면 GIT.md의 필수 검증 조건을 적용한다.
- 독립된 새 에셋을 복제할 때 기존 `.meta`를 그대로 복사해 GUID를 중복시키지 않는다.
- 기존 `.meta`가 누락되면 버전 관리나 백업에서 복구 가능한지 먼저 확인한다. 새로 생성된 GUID를 기존 참조 복구로 간주하지 않는다.
- 추적 대상 에셋은 대응하는 `.meta`와 함께 관리하며 추가·이동·삭제 누락을 확인한다.

## 4. 씬 수정

- 대상 씬과 저장 경로를 확인하고 필요한 오브젝트만 수정한다.
- 저장되지 않은 사용자 변경이 있는 씬을 임의로 닫거나 전체 저장하지 않는다.
- GameObject 이름, 계층, 활성 상태, Transform, Layer와 Tag의 기존 의도를 보존한다.
- Inspector 참조, UnityEvent 연결 및 Missing Script 여부를 확인한다.
- 씬 구성을 요청받은 경우 실행 중 코드 생성으로 임의 대체하지 않는다.
- 신규 UI 작업은 대상 Unity 버전에서 지원되는 경우 UI Toolkit을 기본으로 하고, 기존 Canvas·uGUI·TMP 구성은 별도 마이그레이션 요청 없이 보존한다.
- UI Toolkit 씬 작업에서는 `UIDocument`의 Source Asset(UXML), Panel Settings 참조, UI Document 계층·정렬 설정을 확인한다. 기존 TMP·한글 폰트 연결은 실제 사용 여부를 확인하기 전까지 제거하지 않는다.
- 씬 수정 후 저장·재열기와 필요한 Play Mode 동작을 확인한다.
- 시작 씬이나 빌드 씬 목록 변경은 요청 범위와 연관성이 있을 때만 수행한다.

### 4.1. UI Toolkit 에셋(UXML·USS·PanelSettings) 관리

- UI 문서는 `.uxml`, 스타일은 `.uss`, 런타임 패널 설정은 `PanelSettings` 에셋으로 관리한다. 새 UI는 역할에 맞는 기존 폴더 구조를 사용하며, 위 `UI/` 폴더 예시는 필수 구조가 아니다.
- `UIDocument`의 Source Asset과 Panel Settings, UXML의 템플릿·스타일시트 참조, USS의 `@import`·이미지·폰트 리소스 참조를 변경 전후 비교한다. 파일을 이동·이름 변경하는 경우 `.meta`·GUID를 보존하고 필요한 경로 참조를 모두 갱신한다.
- 여러 화면이 공유하는 `PanelSettings`를 수정하면 해당 패널을 사용하는 모든 `UIDocument`에 영향을 줄 수 있으므로, 실제 사용처와 영향 범위를 먼저 파악한다. 요청 없이 공통 패널을 분리·복제하거나 전체 UI에 일괄 적용하지 않는다.
- 패널의 Scale Mode·기준 해상도, Sort Order, Theme Style Sheet, 입력 및 대상 디스플레이·렌더 텍스처 관련 설정은 설치된 Unity 버전에서 지원되는 실제 Inspector 항목을 확인하여 조정한다. 기존 화면의 스케일·표시 순서가 바뀌지 않도록 검증한다.
- UI Toolkit 한글 텍스트는 대상 버전의 폰트 에셋과 `UITK Text Settings`(또는 해당 버전의 텍스트 설정) 및 fallback 연결을 확인한다. 전체 프로젝트의 기본 폰트·공유 Text Settings를 임의로 교체하지 않으며, 한글·특수문자·입력 문자열이 Editor 및 대상 빌드에서 정상 표시되는지 확인한다.
- USS와 Theme Style Sheet의 공유 범위 및 선택자 이름 변경의 파급 효과를 확인한다. C#의 `Q<T>(...)` 조회나 `AddToClassList(...)`에서 사용하는 UXML `name`·USS class를 바꾸면 해당 코드도 함께 확인한다.
- 새 UXML·USS·PanelSettings·폰트 에셋은 Unity Editor의 정상 임포트로 `.meta`를 생성한다. Editor 확인 없이 GUID·fileID·직렬화 참조의 유효성을 단정하지 않는다.
- UI Builder에서 UXML·USS를 편집하는 경우에도 기존 자산의 이름·서브에셋 참조·기존 사용자 변경을 보존하고, 저장 후 재열기 및 UI 표시를 검증한다.

## 5. 프리팹과 Variant

- 변경을 적용할 위치가 원본 프리팹, Variant 또는 특정 씬 인스턴스인지 먼저 정한다.
- 공통 변경은 적절한 원본에, 특정 인스턴스 전용 변경은 해당 Override에 적용한다.
- `Apply All`이나 `Revert All`로 사용자 Override를 한꺼번에 반영하거나 제거하지 않는다.
- Nested Prefab과 Variant의 상속 관계를 보존한다.
- 요청과 무관하게 프리팹을 Unpack하거나 기존 프리팹을 새 에셋으로 교체하지 않는다.
- 원본 수정 후 사용하는 씬·Variant에서 컴포넌트와 직렬화된 참조가 유지되는지 확인한다.
- 프리팹 에셋에 씬 오브젝트 참조를 저장하는 구조를 만들지 않는다. 필요한 연결은 씬 인스턴스나 초기화 과정에서 제공한다.

---

## 6. 머티리얼과 셰이더

- 현재 렌더 파이프라인에서 지원하는 셰이더와 기존 머티리얼을 우선 사용한다.
- 공유 머티리얼의 변경이 모든 사용자에게 미치는 영향을 확인한다.
- 특정 오브젝트만 바뀌어야 하면 기존 구조에 맞는 머티리얼 분리 또는 속성 제어 방식을 선택한다.
- 머티리얼 복제는 실제로 독립 설정이 필요한 경우에만 수행한다.
- 텍스처 슬롯, 투명도, 렌더 큐와 셰이더 키워드를 필요한 범위에서 확인한다.
- 분홍색 머티리얼 문제를 해결하기 위해 프로젝트 전체의 파이프라인을 임의로 변경하지 않는다.

## 7. 임포트 설정

설정값을 일괄 적용하지 않고 에셋 용도와 대상 플랫폼을 기준으로 판단한다.

| 에셋 | 주요 확인 항목 |
|---|---|
| 텍스처 | Texture Type, sRGB 용도, 크기, 압축, Mipmap, Filter·Wrap Mode |
| 스프라이트 | Sprite Mode, Pixels Per Unit, Pivot, Border, 슬라이스와 Atlas 참조 |
| 모델 | Scale, 축 방향, Rig, Avatar, Animation Clip, 머티리얼 연결 |
| 오디오 | 채널 수, Load Type, 압축, Sample Rate, 스트리밍과 플랫폼별 설정 |
| 애니메이션 | Clip 이름·구간, Loop, Root Motion, Event, Controller 연결 |

- Read/Write는 CPU 접근 등 실제 필요가 있는 경우에만 활성화한다.
- 스프라이트 재슬라이싱이나 모델 재임포트 시 기존 서브에셋 참조가 유지되는지 확인한다.
- 픽셀 아트, 오디오 최적화와 Sprite Atlas 등 전문 작업은 관련 Skill을 함께 확인한다.
- 최적화는 실제 품질과 성능을 확인하며 진행하고 검증 없는 수치를 강제하지 않는다.

---

## 8. ScriptableObject와 공유 데이터

- 공유 설정 에셋과 실행 중 변경되는 상태를 구분한다.
- 런타임 상태를 프로젝트 원본 에셋에 영구 저장하는 구조를 피한다.
- 공유 에셋 수정 전 사용하는 오브젝트와 기능에 미치는 영향을 확인한다.
- 직렬화 필드 이름·타입 변경은 C# 규칙에 따라 기존 데이터의 유지 또는 마이그레이션을 검토한다.
- 원본, 테스트용 에셋과 배포용 데이터를 구분하고 실제 비밀 값을 저장하지 않는다.

---

## 9. 외부 에셋과 로딩 방식

- 외부 에셋의 사용·수정·배포 조건을 확인하고 필요한 출처와 라이선스 파일을 보존한다.
- 패키지 캐시와 `Library` 내부 파일을 직접 수정하지 않는다.
- 외부 에셋을 수정해야 하면 업데이트 시 영향과 기존 확장 방법을 먼저 확인한다.
- 기존 Resources 또는 Addressables 로딩 방식을 무관한 작업에서 교체하지 않는다.
- 경로·주소·라벨·그룹을 변경하면 코드, 설정, 저장 데이터와 원격 콘텐츠에서 사용되는지 확인한다.
- Addressables 콘텐츠 빌드 및 배포 검증은 `BUILD.md`를 함께 따른다.

---

## 10. 이동·삭제와 텍스트 편집

- 삭제 전 씬·프리팹·코드·설정에서 참조 여부를 확인한다.
- 코드 문자열, Resources 경로, Addressables 주소처럼 정적 의존성 검사로 놓칠 수 있는 사용처도 확인한다.
- 참조 검색 결과가 없다는 사실만으로 미사용 에셋이라고 단정하지 않는다.
- 바이너리 에셋을 텍스트 편집하거나 줄바꿈 변환하지 않는다.
- 씬·프리팹 등 직렬화 파일은 Editor 또는 지원 API를 통한 변경을 우선한다.
- 연결 가능한 Editor가 있으면 해당 Editor 또는 지원 API로 수정한다. 텍스트 직접 편집이 필요한 경우 연결 불가 원인과 저장되지 않은 Editor 상태를 먼저 확인하고, 디스크 변경이 사용자 작업과 충돌하지 않는 범위에서 형식·GUID·fileID를 보존하여 최소한으로 수정한다. Unity에서 다시 로드해 검증하며, 실행 불가이면 검증을 완료로 표시하지 않는다.
- 대량 치환, 전체 재직렬화와 무관한 에셋 재임포트를 일반 수정 작업에 섞지 않는다.

---

## 11. 검증과 완료 보고

변경한 에셋 종류에 해당하는 항목만 확인하고 실행하지 못한 검증은 `미확인`으로 보고한다.

- [ ] 에셋과 `.meta`의 추가·이동·삭제가 일치한다.
- [ ] 기존 GUID와 필요한 서브에셋 참조를 보존했다.
- [ ] Missing Script, Missing Reference 및 새로운 임포트 오류가 없다.
- [ ] 프리팹 원본·Variant·씬 Override가 의도대로 유지된다.
- [ ] 관련 씬을 저장·재열기하여 연결과 외형을 확인했다.
- [ ] UI Toolkit 변경 시 UXML·USS·PanelSettings·폰트 및 Text Settings 참조, UI 요소 조회 이름과 표시 순서를 확인했다(해당하는 경우).
- [ ] UI Toolkit 한글·fallback 글리프, 패널 스케일과 대상 플랫폼 표시를 검증했다(해당하는 경우).
- [ ] 필요한 Play Mode와 대상 플랫폼 동작을 확인했다.
- [ ] 불필요한 바이너리 변경·복제·캐시가 결과물에 포함되지 않았다.
- [ ] 실제 프로젝트 변경의 기록과 Git 처리는 `HISTORY.md`, `GIT.md`에 따라 판단했다.

최종 보고에는 변경한 경로, 참조에 미치는 영향, 검증 결과와 필요한 Inspector 설정을 포함한다.
